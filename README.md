# 开机能耗统计

常驻 Windows 通知区域（任务栏右下角）的小工具，统计**本次开机以来**的整机能耗：
开机时长、已统计电量、当前功率与功率构成、平均/峰值功率，以及按**四川省居民阶梯峰谷电价**
折算的电费。右键「用量统计…」还能按**天 / 月 / 年 / 每次开机 / 时段**五种维度翻明细账。

零内核驱动、零管理员权限——不装 WinRing0 之类的东西，不会被安全软件拦。
界面全部由 `user32`/`gdi32` 自绘，**不带 Qt**。

| 实测指标 | 数值 |
| --- | --- |
| 单文件体积 | 7.6 MB |
| 常驻内存（任务管理器「内存」列） | 约 37 MB（另加引导进程 1.6 MB） |
| 空闲 CPU 占用 | 0.00 ~ 0.05% |
| 托盘图标常驻 | 注册表 `IsPromoted=1`，显示在 `^` 箭头左侧 |
| 任务栏长条 | 置顶、可穿透点击的长条窗口，贴在开始按钮左边（默认 651 px 宽 @125%）。**质感 6 档 / 字号 6 档 / 大小 3 档 / 显示内容 15 个字段可勾选**，装不下会自动折行，全在托盘右键菜单里调，改完立刻生效 |
| 测试环境 | Win11 26200 · 2560×1440 @125% · Ryzen 7 5800X + RTX 3080 |

## 快速开始

双击 **`dist\能耗统计.exe`**（单文件，不依赖 Python 环境，可拷到任意位置）。

首次运行会自动：

1. 把图标登记为**常驻任务栏**（即 `^` 箭头左侧常驻显示），并询问是否立刻重启
   资源管理器让设置生效；
2. 弹出详情面板。

| 动作 | 效果 |
| --- | --- |
| 左键单击图标 | 打开 / 收起详情面板 |
| 右键单击图标 | 菜单：显示模式、开机自启、常驻任务栏、**用量统计…**、任务栏长条、**长条质感 / 字号 / 大小 / 显示内容**、电价设置、重置、关于、退出 |
| 鼠标悬停 | 提示：开机时长 + 已统计电量 + 功率构成 + 今日电费 |

图标底色始终代表**当前负载占硬件上限的比例**，与选了哪种显示模式无关：
绿（轻载）→ 琥珀（中载）→ 红（重载）。

图标数字由菜单「图标显示」切换：

| 模式 | 图标上显示 | 说明 |
| --- | --- | --- |
| `current` | 当前功率 (W) | 默认 |
| `cost` | 已用电费 (¥) | 本次统计累计电费，按量级自动调小数位 |
| `session` | 已统计能耗 (Wh / kWh) | 本次统计累计电量 |
| `average` | 平均功率 (W) | 本次统计时段的均值 |

`cost` 模式之所以和负载色分开，是为了能一眼看出「这笔电费是在什么负载下
花掉的」：数字在变，颜色也在变。

> **图标还是藏在 `^` 里？** 菜单里点一次「常驻任务栏」，按提示重启资源管理器即可。
> 也可以手工把它从 `^` 拖到任务栏上。
>
> **电价不对？** 菜单里点「电价设置…」，选省份自动填报，也可以直接改成自己
> 电费账单上的数字，保存即生效。
>
> **图标上的数字看不清？** 见下面「任务栏长条」，开始按钮左边会自动贴一条大字读数。

### 任务栏长条（图标太小看不清的解法）

托盘图标是系统定死的 16~20 px 方块 —— 就算给它一张长条 HICON，系统也会压成
方的，几个数字挤在那点地方必然看不清。所以另外开了一个**置顶、无边框、可穿透
点击**的长条窗口，用接近两倍的字号把读数一次摊开：

```
┌──────────────────────────────────────────────────────────┐
│ 当前 132 W │ 本次电费 ¥0.32 │ 本次电量 428 Wh │ 今日 1.24 kWh │   ⊞ 开始
└──────────────────────────────────────────────────────────┘
```

勾的字段多了塞不进一行时，长条会自动**折行**（最多三行，行高、圆角、竖直居中一并
跟着变），不再是「超了就丢字段」：

几个关键取舍：

| 问题 | 做法 |
| --- | --- |
| 放在哪 | **开始按钮左边**（实测那里是一大片空地）。开始按钮是 `Shell_TrayWnd` 的**子窗口**，必须用 `FindWindowEx` 找（`FindWindow` 永远返回 0，会静默退化成「贴通知区域左边」，位置全错） |
| 会不会抢鼠标 | `WS_EX_TRANSPARENT` 穿透点击 + `WS_EX_NOACTIVATE` 不抢焦点 + `WS_EX_TOOLWINDOW` 不进 Alt+Tab |
| 底色跟任务栏不搭 | 直接 `GetPixel` 采任务栏那一个像素，再往白里调一点当背景；明暗也按**实际像素**判断（本机 `SystemUsesLightTheme=1` 时任务栏却因为「自动」主题 + 深色壁纸是深色的，读注册表会判断反） |
| 右边被任务按钮顶到 | 可用宽度按「开始按钮左边缘 − 20 px 间隙」实测（本机 @125% 是 863 px）。一行装不下就折行；两行还装不下就逐级收紧：折行 → 短标签（「当前功率」→「当前」）→ 缩小分隔间距 → 再小一档字号；始终装不下才从末尾丢字段 |
| 全屏应用盖住屏幕 | 前台窗口铺满整屏时自动隐藏（游戏 / 播放器场景） |
| 圆角要抗锯齿 | 普通窗口画不出带抗锯齿的圆角 —— 走 `WS_EX_LAYERED` + `UpdateLayeredWindow`，自己在 Python 里按圆角矩形 SDF 逐像素写**预乘 alpha** |

> **坑**：GDI 往 32bpp DIB 里画（`FillRect` / `DrawText` 都一样）会把目标像素的
> alpha **直接写成 0** —— 所以补 alpha 时漏掉哪个像素，那个像素在
> `UpdateLayeredWindow` 下就是完全透明的空洞，屏幕上表现为「什么都没显示」。
> 自检里专门有一条守着这件事（`长条内部 alpha 补满（没有透明空洞）`）。

#### 长条长什么样、显示什么，都能自己调

右键图标就有四个二级子菜单，改完**立刻生效**（不用重启、不用重建窗口）：

| 菜单 | 档位 |
| --- | --- |
| **长条质感** | 跟随任务栏（默认）/ 玻璃 / 线框 / 深色卡片 / 浅色卡片 / 强调色 |
| **长条字号** | 极小 0.72（自动折行时的兜底档，菜单里可选）/ 小 0.85 / 标准 1.0 / 大 1.15 / 特大 1.32 / 巨大 1.5 |
| **长条大小** | 纤细 / 标准 / 宽大（胶囊高度 + 左右内边距） |
| **长条显示内容** | **15 个字段**任意勾选（顺序即从左到右的顺序）：当前功率，处理器 / 显卡 / 其他功耗，本次电费 / 电量，今日电量 / 电费，平均 / 峰值功率，开机时长，当前时段，本月电量，累计电量 / 累计电费 |

几条设计约定：

- **默认档必须和以前一模一样**。默认（标准大小 + 标准字号）算出来的胶囊高度比例
  正好是 0.78 —— 老用户升级后长条不会莫名其妙变个高度。字号变大时高度也跟着抬
  （`0.74 + 0.26 × 字号`），否则大字会被上下切掉。
- **装不下时逐级收紧，而不是马上丢字段**。四级：① 折行（一行 → 两行 → 最多三行，
  行高按字号自动算）→ ② 标签换短名（「本次电量」→「本次」）→ ③ 缩小分隔间距
  （分隔 / 间隙按 40% / 70% 压）→ ④ 再小一档字号（0.72）。四级都试过还塞不进，
  才从末尾丢字段。这样「15 个字段全勾」也能一个不丢地排下来。
- **折行后胶囊高度会变**，这是有意的（两行字得有两行的地方）；但**同一组勾选下高度
  必须稳定**。所以排布规划用的是**固定占位数值**（`_PLAN_NUMBER`，按最宽数字算），
  不是实时读数 —— 否则功率从 101 W 跳到 115 W 时规划结果会换档，长条高度跟着跳。
- **至少留一项**。只剩一个字段时，菜单里那一项会变灰、点不动 —— 长条总得显示点什么。
- **顺序就是 `FIELDS` 的定义顺序**，勾选的字段按这个顺序从左到右排。新勾的字段会按
  目录顺序插回原位，不会甩到末尾。
- **勾了「显卡功率」但机器没有能读功耗的独显时**，那一段直接不显示，而不是显示一个
  恒为 0 的假数字。
- **菜单、配置校验、渲染共用 `powermon/stripopts.py` 一份目录**，加档位只改那一个
  文件，不会出现「菜单里有、渲染不认识」。
- 手改 `config.json` 写了菜单里没有的值（比如 `strip_font_scale: 3.0` 会把长条撑爆）
  会在加载时**夹回最近的合法档**。

> **线框（透明底）是怎么做的**：先拿一个颜色铺满胶囊，画完描边和文字，再把底色的
> 像素抠成全透明。这里的关键是**底色必须取「背后的真实任务栏色」**，不能图省事用
> 一个醒目的哨兵色（比如品红）—— 文字是抗锯齿画的，字边那圈像素是「文字色 × 底色」
> 的混合色，底色是品红时它们就真带着品红、而且不等于品红抠不掉，于是整行字镶一圈
> 紫边。底色取真实背景色时，字边的混色恰好就是「文字直接画在任务栏上」应有的颜色，
> 原样保留即正确。
>
> **另一个坑（老代码里就埋着）**：`compose_shape_alpha` 的 `inside()` 是闭包，捕获
> 外层的 `k`；而「边缘」和「阴影」两个分支也往同一个 `k` 里写值。于是每行一旦处理过
> 一个边缘像素，该行之后所有内部像素就都按那个边缘像素的系数去乘 RGB，画面上是
> **规则的横向条纹**。长条以前一直是不透明的 `alpha=255`（走不到那条分支）所以没暴露，
> 加了半透明质感才炸出来。自检里现在有一条纯内存断言守着它
> （`半透明合成逐行一致（没有横条纹）`）。

### 用量统计（按天 / 按月 / 按年 / **按每次开机** / 按时段）

托盘右键 →「用量统计…」，打开一个独立的明细窗口 —— 原生 `SysTabControl32` +
`SysListView32`（报告模式，带网格线和整行选中），不是自绘版面：

| 标签页 | 一行代表什么 | 键 |
| --- | --- | --- |
| **按天** | 一个自然日 | 日期 `2026-09-15` |
| **按月** | 一个月 | 日期前 7 位 `2026-09` |
| **按年** | 一年 | 日期前 4 位 `2026` |
| **按每次开机** | **一次开机**（不是只当前这次） | 内核开机时刻 —— 同一次开机内重开程序接在同一条，重启才是新的一条 |
| **按时段** | 0~23 点中的某一个钟点 | 小时数（跨天累加）→ 一眼看出「几点最费电」 |

列固定为：**时间 / 电量 / 电费 / 运行时长 / 说明**。窗口底部两条单行文字给汇总
（今年 / 本月 / 今天 / 累计，宽度不够时按优先级从低到高截掉，**「累计」永远保留**）
和一句口径提示。窗口大小、选中行、当前页都不落盘 —— 关掉窗口不影响统计，
统计也不会因为没开窗口而断。

> 这一层的账本升级成了**多维记账**：每日 `days`、每次开机 `sessions`、每时段 `hours`
> 三本账并行写，月 / 年汇总在展示时按日期前缀即时归组（单一真源，不另存一份会走样的
> 副本）。升级安装**不会动** `state.json`，历史数据原样接上。

### 窗口圆角

详情面板是一张**整窗圆角卡片**：圆角交给系统切（Win11 原生 8 px、带抗锯齿、
零开销），同时把标题栏底色、边框色、标题字色全对齐到面板自己的配色
（`DwmSetWindowAttribute`），否则会出现「系统灰标题栏里嵌了一张蓝色卡片」的割裂感。
Win10 及更早这些属性不存在，退化成正圆角矩形，其余不受影响。

没自己做「更大半径 + 柔影」的自绘分层窗口，是因为实测把 565×845 的面板过一遍
逐像素 alpha 合成要 **68 ms（无阴影）/ 374 ms（带阴影）**，而面板每秒都会重画，
等于白白吃掉近一个核。长条只有 651×47，同一套代码 3 ms 就跑完 —— 所以分层自绘
这条路给了长条，圆角交给系统给面板。

托盘图标同理：底色是竖向渐变，数字先画一层压暗的 1px 偏移「描边」再叠白色，
最后逐像素写 alpha 并按圆角矩形 SDF 抗锯齿 —— 全是自己算的。

## 四个关键口径

### 1. 「本次开机」怎么算出来的

这是最容易做错的地方。Windows **没有**给出「用户按下电源键」的直接时间戳：

| 口径 | 本机实测 | 问题 |
| --- | --- | --- |
| `psutil.boot_time()` / `GetTickCount64` | 72.7 小时 | 把睡眠、休眠时间也算进去了 |
| `QueryUnbiasedInterruptTime` | 55.5 小时 | 扣了睡眠，但「快速启动」让内核会话跨天延续 |
| **System 日志 `Kernel-Boot` 事件（本程序采用）** | **08:30（4.9 小时）** | 与直觉一致 ✅ |

`Microsoft-Windows-Kernel-Boot` 每完成一次启动（冷启动或快速启动的休眠恢复）
记一条日志，**最新一条就是本次开机时刻**。通过 `wevtapi` 直接读取，
约 1.5 ms，只在程序启动时做一次，读不到时依次回退到
`QueryUnbiasedInterruptTime` → `psutil.boot_time()` → 当前时刻。

同时，这个时刻也是**会话标识**：同一次开机内重开程序会接着上次的账继续记；
第二天早上重新开机则自动开启新会话、独立计账。

### 2. 能耗为什么分「已统计」和「外推估算」

程序只能测到**自己运行期间**的功率。开机后到程序启动前的时段没有实测数据，
所以面板会给出两行：

- **已统计能耗** —— 实测梯形积分累计，单位 Wh/kWh；
- **按均值外推整段开机 ≈ X kWh（估算）** —— 用已统计时段的平均功率外推到整段
  开机时长，仅在统计满 15 分钟且确有缺口时显示，并明确标注为估算。

### 3. 居民电价：内置 30 省预设，每一项都可以改

居民电价是全国最不统一的价目之一：各省单价不同，同一个省内还分档位、
分峰谷时段、部分地区还分丰枯水期。所以电价不是写死的，而是**预设 + 可编辑**：

右键托盘图标 →「电价设置…」：

| 项 | 说明 |
| --- | --- |
| 所在省份 | 内置 30 个省级行政区（数据见 `powermon/tariffs.py` 的 `source` 字段），选完自动填报；第一项是「自定义」 |
| 用电方案 | 同一省份的不同档位 / 计费制式（如一户一表三档、合表用户、是否分时） |
| 峰段 / 平段 / 谷段（枯水、丰水）电价 | 元/度，任意编辑 |
| 峰段 / 谷段时段 | 24 小时制，支持 `8-22`、`23-7`（跨零点）、`11-17,20-22`；留空表示没有该时段 |
| 丰水期月份 | `6,7,8,9,10` 或 `6-10`（可跨年）；留空表示没有丰枯季节差 |

保存即生效（`config.json` 落盘，采样线程与面板共读同一个配置对象，
已经统计进去的历史电费不回头重算）。数字改过之后方案标签会自动标成
「已手动调整」，来源仍指向预设文件，方便日后核对。

计价模型是「峰 / 平 / 谷」三段：`segment_of()` 按时段字符串判定所属段，
同一小时峰段优先；谷段再按 `valley_wet_months` 在丰、枯两个单价间选。
电量按时段分别累计（`peak_wh` / `valley_wh`），跨过 23:00 的统计不会算错。

> 预设里一部分省份（如北京、江苏、湖北等）只有网络汇总口径，没找到官方价目表
> 原文——`Region.verify=True`，设置窗口与详情面板都会标出「建议按电网账单核对」。
> 动手改成自己的数字才是最准的。

### 4. 资源占用

| 项 | 做法 |
| --- | --- |
| 采样 | 后台线程，默认 2 秒一次；CPU 走 PDH、GPU 走 NVML，都是轻量计数器 |
| 界面 | 每个采样周期只更新 1 次；托盘图标**仅在数字变化时**才重画 |
| 面板 | 隐藏时不做任何绘制；绘制走内存位图双缓冲，不闪屏 |
| 依赖 | 无 Qt / 无 Pillow / 无 numpy；`psutil` + `nvidia-ml-py`，打包后单文件 |

### 5. 界面是怎么画出来的

没有 Qt、没有 GDI+，全是最朴素的 `user32`/`gdi32`，所以好看这件事得自己扛：

| 想要的效果 | 纯 GDI 的做法 |
| --- | --- |
| 卡片柔影 | 内存 DC 不支持 alpha，用三层逐级变淡的**偏移圆角矩形**假装 |
| 色块渐变 | 逐行 `FillRect` 做实色插值；图标最多几十行，卡片上百行，开销可忽略 |
| 曲线下方渐变面积 | `CreatePolygonRgn` + `SelectClipRgn` 裁出折线形状，再往矩形里灌渐变 |
| 小号中文标签透气 | `SetTextCharacterExtra` 拉开一丝字距，用完立刻还原 |
| 一屏只有一个视觉重点 | 强调色（蓝）只给「电费」，其余数字一律近黑，层级靠字号和字重 |
| 卡片间距不留死白 | 先量出四张卡片的自然高度，再把窗口富余空间平摊到间距上 |
| 长条的圆角 / 柔影 | 内存 DC 给不了 alpha，走 `WS_EX_LAYERED` + `UpdateLayeredWindow`，在 Python 里按圆角矩形 SDF 逐像素写**预乘 alpha**（见 `roundwin.py`） |
| 整窗圆角 | 交给系统切（`DWMWA_WINDOW_CORNER_PREFERENCE`），标题栏配色对齐到面板自己的色 |

托盘图标同理：底色是竖向渐变，数字先画一层压暗的 1px 偏移「描边」再叠白色，
最后逐像素写 alpha 并按圆角矩形 SDF 抗锯齿 —— 全是自己算的。

## 数据来源

| 部件 | 来源 | 性质 |
| --- | --- | --- |
| **GPU** | NVIDIA NVML（`nvidia-ml-py`） | **实测** |
| **CPU** | Windows PDH `% Processor Utility` + 功耗模型 | **估算** |
| **其他** | 主板 / 内存 / NVMe / 风扇 经验常量 | 估算 |

CPU 的真实封装功耗只能通过 RAPL 读 MSR 寄存器拿到，而 Windows 上读 MSR
必须要一个内核驱动（LibreHardwareMonitor / HWiNFO 用的都是 WinRing0），
会带来驱动签名、安全软件拦截和管理员权限三个麻烦。所以这里用模型：

```
CPU 功耗 = 空载功耗 + (PPT − 空载功耗) × 负载 ^ 0.85
```

负载取自 PDH 的 `% Processor Utility`（Windows 8 引入的「实际有用功」指标，
比任务管理器的 `% Processor Time` 更贴近真实功耗强度）。默认参数按
Ryzen 7 5800X 标定（PPT 142 W、空载 20 W），**典型误差约 ±15%**。

想更准就改 `config.json`：跑一次 Cinebench 把观察到的实际封装功耗填进 `cpu_ppt`，
桌面待机值填进 `cpu_idle`。

## 数据文件位置

`config.json`（设置）和 `state.json`（多维账本）生成在**固定的用户数据目录**
`%LOCALAPPDATA%\PowerMonitor\`，与 exe 装在哪无关 —— 这样升级、换安装路径都不会
把历史账丢掉。首次运行时若在同目录发现旧版便携文件，会**接手**过来继续用。
删掉 `state.json` 等于清零历史累计（每日 / 每次开机 / 每时段三本账一起清）。

## 统计口径

- **能耗**：梯形积分累加（瓦 × 秒 ÷ 3600 = 瓦时），时间基准用单调时钟，
  不受系统对时影响；睡眠留下的大空档直接跳过，不会被乘成虚高能耗。
- **多维账本**：同一个积分结果同时写进三本账 —— 每日（自然日 00:00 分界）、
  每次开机（键是内核开机时刻）、每时段（0~23 点）。月 / 年汇总在展示时按日期
  前缀即时归组，不另存副本。
- **今日累计 / 本次开机**：跨程序重启保留 —— 同一次开机内重开程序接着上次的账
  继续记，第二天重新开机才另开一条「每次开机」记录。
- **开机时长**：见上文「本次开机怎么算出来的」。

## 开机自启

`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，项名 `PowerMonitor`，

## 已知限制

- GPU 只支持 NVIDIA（走 NVML）。AMD / Intel 显卡没有对应通道。
- 台式机没有电池，读不到「整机真实功耗」，CPU 只能靠模型。
- 程序启动前的时段无法测量，只能靠均值外推估算。
- 内置电价预设不是官方价目库：只有约三分之一省份找到了发改委通知或电网
  价目表原文，其余是网络汇总口径（`tariff_verify=True`，界面会标出来）。
  电价也常调整，**以自己电费账单为准**——窗口里每一项都能改。
- 只做居民生活用电口径。工商业、合表、农业电价不在范围内（合表用户只在
  少数省份作为方案列了一档）。
